Install mybench

No NI software needed. Each system needs one thing so mybench can reach the myDAQ.

macOSWindowsLinuxmyDAQ not found

macOS

macOS 14+ · Apple Silicon & Intel
  1. Open the .dmg and drag mybench to Applications.
  2. The app is not notarized yet, so macOS blocks the first launch. Try to open it, then go to System Settings → Privacy & Security and click Open Anyway. On macOS 14, Control-click the app and choose Open.

    Or in Terminal:

    xattr -dr com.apple.quarantine /Applications/mybench.app
  3. Plug in the myDAQ. No driver, no permission prompt.

Windows

BetaWindows 10 / 11 · x64
  1. Run the installer. If SmartScreen warns about an unknown publisher: More info → Run anyway.
  2. Plug in the myDAQ and start mybench. No Zadig, no Device Manager, no reboot.

Works alongside NI ELVISmx. The installer adds a small service, mybench USB access. While mybench runs it borrows the myDAQ through Windows’ own WinUSB driver; when mybench closes, the myDAQ goes back to NI’s driver, so NI MAX, ELVISmx and LabVIEW have it again. If an NI program is using the myDAQ, mybench waits for it to close, or click Use in mybench. The portable .zip has no service: Set Up myDAQ asks for administrator rights once, and the myDAQ then stays on WinUSB until you run bin\mybench-usb-setup release from an administrator prompt.

Linux

x86_64
  1. Install one package: 
    sudo apt install ./mybench_<version>_amd64.deb      # Debian, Ubuntu 25.10+
sudo dnf install ./mybench-<version>-1.x86_64.rpm   # Fedora 42+
flatpak install --user mybench-<version>-linux-x86_64.flatpak
chmod +x mybench-<version>-linux-x86_64.AppImage   # then run it

    The .deb and .rpm need Qt 6.9 or newer from your distribution. The Flatpak fetches the KDE runtime from Flathub if it is missing.

  2. USB access. The .deb and .rpm install a udev rule for you: just re-plug the myDAQ. With the Flatpak or AppImage, add the rule once: 
    echo 'SUBSYSTEM=="usb", ENV{DEVTYPE}=="usb_device", ATTR{idVendor}=="3923", ATTR{idProduct}=="755b", MODE="0660", GROUP="plugdev", TAG+="uaccess"' \
  | sudo tee /etc/udev/rules.d/60-mybench-mydaq.rules
sudo udevadm control --reload-rules && sudo udevadm trigger

    Then re-plug the myDAQ. On a desktop session that is all; without systemd-logind, also add yourself to plugdev and log in again. Fedora has no plugdev group and doesn’t need one.

myDAQ not found?

A myDAQ that is plugged in but can’t be opened shows as Not available, with the reason.

With NI software
Windows: an NI program is using the myDAQ. Close it, or click Use in mybench.
Needs setup
Windows: the mybench USB service is not running. Reinstall mybench, or click Set Up myDAQ.
No permission
Linux: add the udev rule (above).
In use
Another program has it open. Close it, then Rescan.
Open failed
Just plugged in, or a hub or cable. mybench retries; re-plug if it stays.

Firmware. The myDAQ needs a current NI firmware. A myDAQ that was used once with a recent NI ELVISmx or NI-DAQmx has it. With an older one, the multimeter and digital I/O work, but analog input and output don’t until the myDAQ has been connected once to a computer with NI’s software. mybench never writes to the device.

No myDAQ at all? mybench opens a simulated one. Every instrument works.
